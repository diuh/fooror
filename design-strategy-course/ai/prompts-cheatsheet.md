# AI-шпаргалка курсу «Design Strategy»

> Усі промпти курсу в одному місці. Формат кожного — **Ціль → Промпт → Застереження**.
> **Колір-тег:** ⬛ чорний (AI-крок).

---

## Наскрізний принцип: AI чернетить — дизайнер вирішує

AI прискорює **рутину**: згенерувати питання, звести нотатки, знайти патерни, перевірити логіку. Але **судження** — про перевагу, позиціювання, рішення — лишається за людиною. Три правила безпеки:

1. **Годуй фактами, не проси вигадувати.** Реальні цитати, реальний бриф → корисно. «Придумай аудиторію» → правдоподібна фантазія.
2. **Розділяй факт і гіпотезу.** Проси AI позначати `[ФАКТ]` / `[ГІПОТЕЗА]` і перевіряй усе, що він видав за факт.
3. **Фінальне рішення — твоє.** AI дає чернетку й варіанти; обираєш і формулюєш ти.

## Модуль 0 — Орієнтація в ніші
**Ціль:** швидка стартова карта незнайомого ринку.
```
Ти — досвідчений продуктовий дизайн-стратег. Я починаю проєкт: [тип проєкту]
у ніші [ніша], ринок [країна/регіон]. Дай стартову карту: 1) ключові гравці,
2) типові рішення (ймовірні POP), 3) де ховається диференціація (напрями POD),
4) 5 питань, які треба прояснити на брифі. Познач факт vs припущення.
```
⚠️ Гіпотези, не істина. Конкурентів і тренди перевіряємо в М2–М3 руками.

## Модуль 1 — Бриф

**1.1 Питання під нішу**
```
Я готую бриф для проєкту: [тип] у ніші [ніша], ринок [регіон]. Згенеруй питання
по блоках (ціль бізнесу, продукт/УТП, ринок, функціонал, аудиторія, обмеження,
ризики). До кожного — колонка «навіщо» (яке дизайн-рішення розблоковує).
Прибери питання без чіткого «навіщо».
```
**1.2 «Допит» брифу на прогалини**
```
Ось мій бриф: [бриф]. Виступи адвокатом диявола: які питання без відповіді?
Де суперечності? Які припущення я зробив без перевірки? Дай список уточнень клієнту.
```
**1.3 Сирі нотатки → структуроване ТЗ**
```
Ось нотатки з дзвінка: [нотатки]. Структуруй у бриф по блоках. Де бракує даних —
познач [ПОТРІБНО УТОЧНИТИ]. Нічого не вигадуй.
```
⚠️ Перечитай — AI може «дофантазувати» факти. Пробіли лишай позначеними.

**1.4 Швидкий шлях — скіли Claude Code**
Замість промптів вище: `Small Talk для [проєкт, ніша]` → далі в тому ж чаті `а тепер бриф під цей проєкт`.
Скіл `brief-generator` бачить попередній Small Talk і не дублює його питання, а перетворює на уточнення.
Встановлення — `.claude/skills/README.md`.

## Модуль 2 — Конкурентний аналіз

**2.1 Розширити список конкурентів**
```
Досліджую ринок [ніша], регіон [країна]. Склади список конкурентів: прямі,
непрямі, аспіраційні; для кожного — чому в цій групі. Додай сегменти, які я міг
проґавити. Познач як гіпотези для перевірки.
```
**2.2 Критерії з брифу**
```
Ось бриф: [бриф]. Запропонуй критерії конкурентного аналізу (функціонал/UX/візуал/
позиціювання/пропозиція/довіра). Для кожного — чому він важливий саме тут.
```
**2.3 Нотатки → матриця**
```
Ось нотатки по конкурентах: [нотатки]. Зведи в таблицю конкуренти × критерії.
Де даних нема — «—», не вигадуй. Познач кандидатів у POP (є майже в усіх)
і POD (білі плями).
```
**2.4 Формулювання переваги**
```
На основі POP/POD: [список] сформулюй 1–2 переваги за формулою: «На відміну від
[конкуренти], які [POP], ми [POD], що важливо для [аудиторія], бо [причина]».
Дай 3 варіанти.
```
⚠️ Кожного конкурента відкриваємо руками. POD/POP — гіпотези, рішення за дизайнером.

## Модуль 3 — Трендвотчинг

**3.1 Напрями трендів**
```
Шукаю тренди для [тип] у ніші [ніша], ринок [регіон]. Дай: макротренди,
UI-патерни для розгляду, суміжні ніші для свіжих ідей. Для кожного — чому доречно.
Це напрями для пошуку референсів, не готові рішення.
```
**3.2 Розбір патерну за скріншотом** (з картинкою)
```
Ось скріншот: [зображення]. Який UX/візуальний принцип тут працює і чому?
Що переймається, а що — специфіка цього продукту?
```
**3.3 Референс → POD**
```
Наш POD: [POD]. Референси й принципи: [список]. Для кожного — який POD він
підсилює і як проявити в UI. Познач слабкі звʼязки.
```
**3.4 Варіації реалізації**
```
POD: [POD]. Принцип: [принцип]. Дай 5 способів втілити це в UI [екран]
для аудиторії [хто], з різними рівнями сміливості.
```
⚠️ AI не бачить свіжих сайтів — референси шукаємо очима. Ідеї = чернетки для скетчів.

## Модуль 4 — Аудиторія і персона

**4.1 Патерни з цитат**
```
Ось цитати/відгуки в ніші [ніша]: [цитати]. Згрупуй у патерни: JTBD, болі,
барʼєри, тригери. Підтверджуй цитатою. Припущення без доказів — [ГІПОТЕЗА].
```
**4.2 Чернетка прото-персони**
```
На основі патернів: [патерни] склади прото-персону: контекст, JTBD, болі,
барʼєри, тригери, очікування від UI. Кожен пункт — [ФАКТ]/[ГІПОТЕЗА]
+ колонка «наслідок для дизайну».
```
**4.3 JTBD**
```
Сформулюй 3–5 JTBD для [опис] у форматі «Коли [ситуація], я хочу [мотив],
щоб [результат]». На основі болів: [болі].
```
**4.4 Стрес-тест персони**
```
Ось персона: [персона]. Скептично: які припущення не підкріплені? Де я спроєктував
власні смаки? Які болі пропустив? Що перевірити перед опорою на цю персону?
```
⚠️ Годуй реальними цитатами. Персона — інструмент, не «паспорт з фото».

## Модуль 5 — Дизайн-стратегія

**5.1 Чернетка стратегії**
```
Висновки дослідження: Бриф [М1]; Конкуренти/POD/POP [М2]; Тренди [М3]; Персона [М4].
Збери чернетку стратегії: бізнес-ціль, аудиторія, перевага, позиціювання,
дизайн-принципи, прояв в UI, метрики. Для кожного пункту — з якого блоку випливає.
```
**5.2 Дизайн-принципи**
```
На основі POD [POD] і болів [болі] сформулюй 4–5 принципів за формулою
«Ми [так], а не [інакше], тому що [інсайт]». Короткі, придатні для рішень у макетах.
```
**5.3 Перевірка на розриви**
```
Ось стратегія: [стратегія]. Перевір: 1) кожен принцип спирається на дослідження?
2) немає суперечностей? 3) перевага відображена в принципах і UI? 4) що пропущено?
Дай список конкретних дірок.
```
⚠️ Логіку трасування (принцип ← інсайт) перевіряєш ти. Принцип без джерела — прибирай.
