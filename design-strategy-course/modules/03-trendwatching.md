# Модуль 3 — Трендвотчинг і референси

> **Артефакт:** FigJam-moodboard + таблиця «референс → принцип → наш POD». Заповнений приклад — moodboard UV з привʼязкою до переваги.
> **Колір-тег:** 🟨 жовтий (візуальні гіпотези).

---

## Ціль модуля

Навчити відрізняти трендвотчинг від сліпого копіювання, знати де шукати якісні референси і — головне — перетворювати референс на **конкретне рішення для втілення POD**.

---

## Теорія

### Трендвотчинг ≠ копіювання

Копіювання — «беру гарне і повторюю». Трендвотчинг — «розумію, **який принцип** тут працює і **чому**, і застосовую під свою задачу». Референс — це не картинка, яку крадуть, а **доказ, що прийом працює**.

Два рівні трендів:
- **Макротренди** (індустрія): куди рухається e-commerce загалом — подача, формати, підходи.
- **Мікротренди** (UI-патерни): конкретні рішення — тип каталогу, картка товару, мікровзаємодії, типографіка.

Дизайнеру потрібні обидва: макро задає напрям, мікро дає інструменти.

### Де шукати референси

| Джерело | Для чого |
|---------|----------|
| **Behance, Dribbble** | концепти, візуальні напрями (обережно: часто нереалізовні) |
| **Awwwards, Godly, Land-book** | живі сайти високого рівня, реальні рішення |
| **Mobbin** | реальні UI-патерни й флоу (особливо моб.) |
| **Реальні конкуренти (М2)** | що працює саме в ніші й на ринку |
| **Суміжні ніші** | свіжі ідеї, яких немає в твоїй ніші (джерело POD) |
| **Pinterest / фізичний світ** | настрій, естетика, бренд-мова |

Правило: **баланс галерейного (натхнення) і реального (доказ, що працює в продакшені).** Тільки Dribbble → красиві, але непрацездатні макети.

### Від референсу до реалізації POD (ядро модуля)

Ланцюг із трьох питань перетворює «мені подобається» на рішення:

```
1. ЩО мені подобається?      → конкретний елемент (не «весь сайт»)
2. ЯКИЙ принцип працює?      → чому це ефективно (механіка, не зовнішність)
3. ЯК застосувати до НАШОГО POD? → рішення під нашу перевагу й аудиторію
```

Без кроку 3 референс лишається чужим. Саме привʼязка до POD (з М2) робить трендвотчинг стратегічним, а не декоративним.

---

## Приклад UV: moodboard із привʼязкою до POD

На кейсі UV показуємо не «дошку красивих картинок», а робочу таблицю:

| Референс (що подобається) | Принцип, що працює | Наш POD, який це підсилює |
|---|---|---|
| Спосіб подачі товару в сильному бренді | великі візуали + повітря → відчуття якості | POD «сильніша подача бренду, ніж у конкурентів» |
| Каталог із зручними фільтрами (реальний сайт) | швидкий шлях до товару → менше фрустрації | POD «кращий UX каталогу» |
| Мікровзаємодії/акценти з аспіраційного референсу | керують увагою на ключових діях | підсилення конверсійних сценаріїв |

> На полотні: зліва — референси (скріншоти зонами: макротренди / UI-патерни / **анти-приклади**), справа — та сама таблиця «референс → принцип → POD». Анти-приклади («так не робимо і чому») не менш цінні за приклади.

---

## Твій шаблон

**Зона moodboard** з трьома під-зонами:
- `Макротренди` — загальні напрями індустрії.
- `UI-патерни` — конкретні рішення (каталог, картка, навігація, мікровзаємодії).
- `Анти-приклади` — що НЕ робимо і чому.

**Таблиця «референс → принцип → POD»** (3 колонки) — обовʼязкова: кожен референс має закінчитись привʼязкою до конкретного POD з модуля 2. Референс без POD → на полотно не потрапляє.

## AI-кроки

### AI-крок 1 — напрямки трендів для ніші

**Промпт:**
```
Я шукаю візуальні й UX-тренди для проєкту [тип] у ніші [ніша], ринок [регіон].
Дай: 1) макротренди індустрії, 2) конкретні UI-патерни, які варто розглянути,
3) суміжні ніші, де можна підгледіти свіжі ідеї. Для кожного — чому це доречно
саме тут. Познач, що це напрями для пошуку референсів, а не готові рішення.
```
**Застереження:** AI не «бачить» свіжих сайтів — він дає напрями. Самі референси шукаємо очима в джерелах вище.

### AI-крок 2 — описати патерн за скріншотом

**Промпт (з картинкою):**
```
Ось скріншот інтерфейсу: [зображення]. Опиши, який UX/візуальний принцип тут
працює і ЧОМУ він ефективний. Що саме можна перейняти, а що — специфіка цього
продукту й не переноситься?
```
**Застереження:** перевір висновок власним судженням — контекст продукту AI знає лише з картинки.

### AI-крок 3 — звʼязати референс із POD

**Промпт:**
```
Наш POD: [перелік POD з М2]. Ось референси й принципи, які я зібрав: [список].
Для кожного пришвидшено запропонуй, який саме POD він міг би підсилити і як це
проявити в інтерфейсі. Познач слабкі звʼязки, де референс не працює на наш POD.
```
**Застереження:** фінальний відбір — за дизайнером. Мета — підсилити перевагу, а не «наліпити трендів».

### AI-крок 4 — варіації ідей реалізації

**Промпт:**
```
POD: [POD]. Принцип із референсу: [принцип]. Запропонуй 5 різних способів
втілити це в UI [тип екрана, напр. каталог/картка товару] для аудиторії [хто].
Коротко, по суті, з різними рівнями сміливості.
```
**Застереження:** ідеї — це чернетки для скетчів, не готові макети. Фільтруй під бренд і реалістичність.
